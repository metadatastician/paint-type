== Overview

This document provides a comprehensive matrix of automation coverage across all DEPs, including CI/CD workflows, drift detection, status gates, and verification mechanisms.

**Automation Categories:**
- *CI/CD Workflows*: GitHub Actions workflows for build, test, and verification
- *Status Gates*: Automated checks that prevent regressions (proof counts, test counts)
- *Drift Detection*: Mechanisms to detect and prevent documentation/code drift
- *Verification Scripts*: Automated verification of claims and invariants
- *Machine-Readable*: a2ml, JSON, or other structured formats for tooling

**Coverage Levels:**
- *✅ Full*: All critical automation in place and working
- *⚠️ Partial*: Some automation in place, gaps identified
- *❌ None*: No automation
- *🟡 Planned*: Automation planned but not yet implemented

== Automation Best Practices

=== What Makes Good DEP Automation?

1. **CI/CD Workflows:** Every DEP should have at least basic CI/CD
2. **Status Gates:** Proof/test counts should be gated to prevent drift
3. **Drift Detection:** Automated detection of stale documentation/code
4. **Verification Scripts:** Automated verification of claims
5. **Machine-Readable:** Structured metadata for tooling consumption

=== Estate-Wide Standards (DEP-09)

DEP-09 standards provides reusable workflows and scripts:

[cols="3,1,1"]
|=== 
| Resource | Type | Usage |
| governance-reusable.yml | Workflow | Reusable governance |
| codeql-reusable.yml | Workflow | CodeQL analysis |
| build-registry.sh | Script | Registry generation |
| build-scorecards.sh | Script | Scorecards generation |
| verify-manifests.yml | Workflow | Manifest verification |
|=== 

**All DEPs should:**
1. Use standards reusable workflows where applicable
2. Run build-registry.sh --check in CI
3. Run build-scorecards.sh --check in CI
4. Verify manifests in CI
