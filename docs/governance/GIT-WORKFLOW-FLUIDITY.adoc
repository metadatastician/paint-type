= Git Flow & CI/CD Fluidity Guide (`paint.type`)

== Root Causes Diagnosis

Auditing pull requests `#129` through `#140` against active GitHub organization
rulesets (`18225024` `EstateBranching`, `24634124` `Branch-Signatures`, and
`23868655` `Branch-Floor`) and `hyperpolymath/standards` (`D213`, `D324`, and
`ULTRAPLAN-KAUTZ-LADDER-2026-10-19.adoc`) isolated six concrete mechanisms that
previously created multi-hour PR friction:

1. **Stacked bot PRs + squash-only merges (`PR #132`, `PR #138`):**
   `paint-type` enables squash merges only (`allow_squash_merge: true`,
   `allow_merge_commit: false`). CodeRabbit's default finishing-touch docstring
   generator opens stacked child PRs (`coderabbit/document-changed-functions/*`)
   against the feature PR branch. The instant the parent PR squash-merges into
   `main`, GitHub retargets the child PR onto `main`, guaranteeing a 3-way
   history conflict (`mergeable: CONFLICTING`), while direct bot pushes are
   refused by policy (owner ruling `D324`).
2. **CodeRabbit path trap (`.coderabbit.yaml` at root vs `.github/`):**
   CodeRabbit v2 reads `.coderabbit.yaml` strictly from the repository root and
   falls back to `Organization UI` (`ASSERTIVE`) when placed inside `.github/`.
   Root placement requires registering `.coderabbit.yaml` in
   `.machine_readable/root-allow.txt` with an explicit `Ratchet-exception:`
   commit trailer.
3. **Split branch-signature rulesets (`24634124` vs `18225024`):**
   `Branch-Signatures` (`24634124`) exempts `refs/heads/arena/**` on push,
   allowing unsigned local commits onto feature branches, whereas
   `EstateBranching` (`18225024`) enforces `required_signatures: true` on
   `main`, blocking merge only after CI finishes. In addition, `24634124`
   lists `refs/heads/coderabbitai/**` whereas CodeRabbit branches use
   `refs/heads/coderabbit/**`.
4. **Assertive bot nitpicks + `required_review_thread_resolution: true` + `dismiss_stale_reviews_on_push: true`:**
   Under CodeRabbit's org-default `ASSERTIVE` profile, minor stylistic notes open
   blocking review threads; pushing fixes then dismisses prior CODEOWNERS
   approvals, forcing repeated human re-approval cycles. Meanwhile
   `chatgpt-codex-connector` triggers automatically on every PR open and posts
   two failure comments when quota is exhausted.
5. **Late CI discovery of fast static invariants:**
   `actions.lock` closure, Hypatia rules (`WH001`, `WH006`, `RE001`, `RE005`,
   `js_exec_sync`, `hardcoded_tmp`), `panic-attack` weak-point rules, D43
   `.a2ml` freeze rules, `Ratchet-exception:` trailers, and invisible Unicode
   previously ran only after queueing 70+ GitHub Actions jobs.
6. **Lockfile & allowlist merge collisions:**
   Concurrent PRs editing `.github/workflows/*.yml` or
   `.machine_readable/root-allow.txt` collided on adjacent lines.

== Recommended Daily Developer & Agent Flow

[source,bash]
----
# One-time setup in any local clone:
just install-hooks

# 1. Stage intended changes and publish the initial signed commit + remote branch
#    BEFORE opening the Draft PR (avoids any unsigned local commit hitting pre-push):
git checkout -b feat/core-example
git add <files>
just push-signed "feat(core): initial draft implementation" "Optional body details"

# 2. Open the Draft PR (skips review noise while CI validates):
gh pr create --draft --fill

# 3. Iterate as needed; if workflows changed, regenerate actions.lock first:
just sync-lock
git add <files>
just push-signed "fix(core): follow-up refinement"

# 4. Once CI checks are green, mark ready for single-pass review + approval:
gh pr ready
----

== Four Optional Organization / App UI Tweaks (Owner UI Only)

1. **Set Codex review trigger to manual `@codex review` only (`chatgpt.com/codex/cloud/settings/general`):**
   Eliminates the two automatic `You have reached your Codex usage limits`
   failure comments on every newly opened PR while keeping on-demand `@codex review`.
2. **Allow repository `.coderabbit.yaml` overrides in CodeRabbit Org Settings (`app.coderabbit.ai`):**
   Ensure Organization UI settings permit repository `.coderabbit.yaml` files to
   override `ASSERTIVE` profile defaults once merged to `main`.
3. **Review `dismiss_stale_reviews_on_push` and `require_last_push_approval` together in Ruleset `18225024` (`EstateBranching`):**
   Both settings interact: disabling `dismiss_stale_reviews_on_push` alone still
   blocks merge on a new push while `require_last_push_approval` remains `true`,
   and disabling `require_last_push_approval` alone still dismisses the existing
   approval on a new push while `dismiss_stale_reviews_on_push` remains `true`.
   Toggling both only if desired (or using Draft PRs until ready) avoids repeat
   approval rounds on trivial post-review fixes.
4. **Disable Copilot auto-review on Draft PRs in Ruleset `18225024` (and add `refs/heads/coderabbit/**` to `24634124` if needed):**
   Flip `copilot_code_review.parameters.review_draft_pull_requests` from `true`
   to `false` to match `.coderabbit.yaml` `auto_review.drafts: false`.
